# Browser extension 1.2.0 release check

The comparison build was `076b388e400ce104a5b3ea60544f644f3d9d1fcf`, the 1.1.0 manifest on main. Both builds used the extension repository’s lockfile, Node 24.18.0, the production esbuild configuration, and the same Apple M5 Pro on macOS 26.6.2 with Google Chrome 158.0.8127.88. The three DataFog package versions and integrity hashes match the baseline.

## Footprint and responsiveness

| Measurement                                       | 1.1.0 baseline |      1.2.0 |
| ------------------------------------------------- | -------------: | ---------: |
| Release ZIP, bytes                                |      5,497,118 | 32,115,767 |
| Unpacked file contents, bytes                     |     13,107,491 | 76,315,453 |
| First native paste, ms                            |           93.5 |      375.9 |
| Median of three subsequent pastes, ms             |           28.6 |       60.2 |
| Peak sampled Chrome process RSS during paste, MiB |          1,104 |      1,536 |

The ZIP grew by 26,618,649 bytes and the unpacked extension by 63,207,962 bytes. The Rampart assets and worker occupy 39,203,363 bytes, LiteParse’s WASM and accompanying license occupy 20,649,281 bytes, and the OCRia assets and license occupy 1,473,472 bytes. The baseline shipped two copies of Core’s 5.1 MiB WASM and no standalone ONNX Runtime Web WASM. The new model and PDF workers load on demand.

For paste timing, a new browser profile enabled automatic masking and pasted the test harness’s email and credit card sample into the Claude fixture. Timing ran from the native paste event to the first animation frame containing both replacements. Each build used its default detector: CNN in 1.1.0 and Rampart in 1.2.0. These single-machine observations describe this run. Three warm samples provide limited precision.

The PDF measurement used eight alternating copies of the mixed and scanned fixture pages, combined with Poppler’s `pdfunite` (186,056 bytes). From file selection, extraction finished the first page in **1.35 s** (the start of page two) and the full review was available in **4.93 s**. A concurrent native paste finished in **412 ms**. Peak sampled Chrome process RSS during that scan was **1,850 MiB**. RSS sums the processes of the isolated test browser using DevTools process IDs and macOS `ps`. It includes Chrome overhead and may count shared memory more than once.

## What reached the chat draft

Native, scanned, and mixed single-page fixtures contained the same six labeled components. The parser recovered each component exactly once in all three files. The mixed page contained embedded prose and email plus a rasterized address. Source recovery and final masking were evaluated independently.

On the mixed PDF, using the default reversible action for every detected finding, the CNN masked the email and unit. Rampart masked the full name, email, street and city/region/postal line. Of six components intended for protection, **4/6 remained identifiable with CNN and 2/6 with Rampart**. Both missed the standalone first name Jane. Rampart also missed Unit 4 in this document. Both left part of the mailing address identifiable when scored as one complete address.

The separate detector-only comparison covers 10 synthetic inputs and 11 labeled values. It includes false replacement counts, exact spans by language, a Unicode offset regression, and the limits of the dataset. See [the comparison](RAMPART_EVALUATION.md) and [individual results](detector-comparison.json).

The ChatGPT-style provider fixture recorded editor mutations and intercepted its outgoing send request. The reviewed three-email example produced one reversible placeholder, one permanent label and one intentionally preserved email. Only the reversible original was present after restarting the vault. The fixture received the approved text on explicit send. Changing the draft, switching tabs, or injecting a vault commit failure prevented insertion. Earlier chunk mappings can remain in the vault if a later chunk fails. Authenticated provider sites, Microsoft Edge and non-Latin OCR were outside this run.

## Reproduce the release checks

```sh
npm ci
npm audit --omit=dev
npm run format:check
npm run lint
npm run typecheck
npm test
npm run package
node scripts/check-release.mjs --tag v1.2.0
PDF_EVAL=1 npm run test:integration
```

The PDF integration tests load the unpacked production extension in Chrome. The mixed-PDF tests set the browser context offline. To inspect one workflow, use `PDF_EVAL=1 npx playwright test e2e/pdf-review.spec.ts` after building. The fixture inputs and gold text are in `e2e/pdf-fixtures/`. Upstream [ParseBench](https://github.com/run-llama/ParseBench) evaluates document extraction. The release checks here measure what remains visible after extraction, detection, user choices and draft insertion.

The release workflow publishes a tagged commit after it reaches main. This release check covers a local package.
